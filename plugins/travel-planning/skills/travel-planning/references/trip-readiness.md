# 行前就绪检查

路线确认后、精确排日程前执行。目标是把“路线在纸面上可行”推进到“旅行者能安全衔接、知道何时预订和何时复核”。结果写入 `planning.readiness[]` 与 `planning.booking_tasks[]`。

## 条件触发规则

### 所有行程

- 检查旅行日期是否撞上法定节假日、地方节庆、大型赛事/演出、宗教时段、每周闭馆日、季节停运或维护期。公共节假日列表不能替代城市活动和单个景点公告。
- 记录当地紧急电话、旅游或非紧急求助入口、住宿/承运方应急联系方式。号码必须来自官方来源并带 `checked_at`；页面不能暗示系统可代替用户呼叫。
- 收集步行承受度、无障碍需求、老人儿童、饮食禁忌/过敏、海拔与高温耐受、夜间出行限制。缺少这些信息时只做低风险默认，不得假设“无障碍需求”。
- 对退房到入住、跨城换乘、景区寄存和一日包车写清大件行李在哪里。车站寄存、酒店寄存或司机保管都必须说明营业时间、容量/件数限制和备选。
- 给出与季节、温差、降雨、紫外线、蚊虫、徒步或雪地相匹配的精简衣物与装备清单；健康风险只作准备提示，不作诊断。
- 将动态项目分为 `book_now`、`book_when_open`、`recheck_later`、`optional`。有容量风险的可退订方案优先，非退订项目应在路线和关键日期稳定后再买。

住宿默认按[住宿区域规划](lodging-planning.md)由用户选店。未选酒店时不搜应急联系方式或声称酒店寄存、提前入住、停车与充电已确认；只列影响行程的选店条件。明确依赖这些服务的衔接须有缓冲和替代方案；其余酒店待选不阻断区域方案交付。

### 境外或跨境行程

- 入境与签证只用目的地政府、移民部门、使领馆等官方来源，并以旅行者护照、停留目的和日期为输入。不得凭记忆下结论。
- 每个过境机场都要检查是否需要入境、过境签、重新托运行李、跨机场、机场夜间关闭或过夜住宿。分开出票默认按“可能需要自行提取并重新托运”核验。
- 记录护照有效期/空白页、入境材料、旅行登记或健康要求。医疗和疫苗建议转介官方卫生机构或合格专业人士。
- 记录官方旅行安全提示、保险的医疗/取消/高风险活动/租车责任范围及紧急援助电话；只说明保单可核验内容，不替用户判断一定获赔。
- 货币换算必须写汇率来源、币种和日期；预算同时保留原币与用户常用币，说明银行卡境外手续费、动态货币转换和现金需求。
- 记录 eSIM/SIM、语音电话需求、漫游、插头、电源、常用支付与交通 App、离线地图和重要文件备份。需要司机或旅行团电话确认时，数据流量卡不能自动视为足够。
- 跨时区行程的日期、航班到达日和酒店入住夜必须逐项对齐。红眼航班后降低首日强度，并确认凌晨入住或行李寄存。

## 交通专项检查

- 每个航班方案记录票价是否含税、是否按人、手提/托运行李额度及额外费用、机场和航站楼、当地出发/到达日期与时区、退改条件。
- 分开出票、自行中转或跨机场时，记录最小缓冲、行李路径、入境/安检路径和错过后一段的责任承担；不能只比较票面价格。
- 铁路和大巴记录实名/证件要求、开售窗口、行李规则、夜间到达后的末班接驳。
- 租车或包车记录车辆/司机资质、保险责任、押金、油路桥停车、异地还车/返空、司机食宿、超时费、儿童座椅、冬季装备和取消规则。小红书只用于发现体验问题，再回到合同或平台核实。

## 分阶段复核

天气按[研究深度](research-depth.md)研究。优先复用同地点一次查询中的实际日期预报；季节对象可覆盖多个适用日期，单日预报不可扩写。天气敏感活动深化相关字段与实际调整方案；远期普通活动保留季节风险和临近复核，不用当前预报填未来日期。

根据行程日期生成实际日期，不机械照抄相对时间：

- `T-30～T-14`：签证/证件、保险、热门门票、节假日与大型活动、交通开售、包车书面报价。
- `T-7`：中期天气、景区临时公告、交通运行、住宿与接送确认、装备清单。
- `T-3`：预警、降雨/高温/降雪、车次航班变化、餐厅与预约、司机/接送书面确认。
- `T-1`：实时交通、入口、停止入场、电子票/证件、行李方案和紧急联系方式离线备份。

长期未来日期无法核验到具体营业时间时，记录“季节性规律 + 核验日期”，并创建临近出发的复核任务，不把规律写成该日已确认事实。
T-7 之前的逐日天气只作为低置信度风险信号，用来准备室内或缩短版备选，不得仅凭一次远期模型结果取消基础行程或写成确定天气；进入 T-7 后再根据连续更新调整执行顺序。

## 数据与呈现

`planning.readiness[]` 每项至少包含：

- `id`、`category`、`status`、`summary`。
- 适用时增加 `deadline`、`checked_at`、`source_ids`、`action_links`。
- `status` 使用 `verified`、`platform_reported`、`estimated`、`to_recheck` 或 `not_applicable`。
- `to_recheck` 必须带能执行复核的 HTTPS `action_links[]`，链接标签写出地点、日期和待核字段。

不把护照号、保单号、电话、真实订单号等敏感信息写入共享研究目录或最终 HTML；只保留“用户需携带/核对”的任务描述。
