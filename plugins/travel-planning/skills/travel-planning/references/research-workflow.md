# 景点与路线研究

本文件只说明如何从候选景点形成可执行路线。字段结构见[行程数据结构](itinerary-schema.md)，子 Agent 完成门槛见[子 Agent 编排](agent-orchestration.md)。

## 1. 建立景点候选

先根据用户兴趣、同行限制、季节与节奏列出待证问题，用网页搜索阅读相关官方资料、公开攻略、媒体和亲历游记，建立玩法候选。小红书可用时补充近期正文、必要图片和评论，高德可用时补充入口与路线；两者可用仍执行公开网页研究。候选也可由用户资料或社区发现，再回到其他渠道交叉核验。记录具体体验、用户适配、取舍、正反证据与冲突，不把热度或地图排序等同于适合。搜索标题与摘要只用于发现。来源无法读取时记录具体缺口，再查询其他原始来源，未查到的动态事实不从模型记忆补造。

每个候选至少研究：

- 名称、区域、坐标或可定位地址，以及分开的实体地址、官网、公告和预约入口；预约主要在微信公众号完成时，核验公众号名称、微信内菜单路径和官方说明文章入口。
- 当季看点、最佳时段、普通游览时长、体力与天气限制；体验来源注明月份和查询日期。
- 适用日期的开放、停止售票、停止入场、闭园、节假日覆盖、临时公告和查询时间。
- 推荐入口、入口理由、建议出口，以及入口到出口的 checkpoints。每个节点记录时间、类型、必达性、动作，并按需要附有来源的讲解、图片、内部交通、补给、费用、链接和失败备选。没有查到节点看点时留空，不生成全景区重复的通用句。
- 基础门票、景区内必选交通、可选体验和互斥套票，分别记录计价、数量、小计、基线角色、状态和来源。
- 预约任务的目标日期或场次、人数、产品、放票规则、下一动作、截止、无票备选和官方入口。
- 对应日期的天气对象；只有会改变动作的天气影响进入 checkpoint 条件或备选。

社区内容只用于近期体验、拥挤、昼夜效果和避坑，开放、票价、入口与安全规则回到官方来源。图片只使用用户素材、官方允许素材或开放许可素材；社区图片以原帖链接卡呈现。

## 2. 形成交通边

先按[研究深度](research-depth.md)决定哪些边会影响方式选择、硬时间或可行性。普通同片区移动可复用已有区域资料，用门到门区间加缓冲；复杂换乘、末班或硬预约等再深入核对，不默认每条边都查实时路线、多个方式与报价。

分别研究出发地到目的地、站点到住宿或首景点、住宿到每日首景点、相邻景点出口到下一入口、末景点到住宿，以及返程或下一城市。

住宿默认是[区域建议](lodging-planning.md)。以具名公开代表地标作为大概位置，锚点注明 precision=area，相关段使用有依据的区间估算与缓冲，不为获得酒店精确起终点而启动逐家酒店比选。用户给出酒店地址后再细化衔接。

每条边至少记录（工具无关）：

- 适用方式及可执行备选，包括步行、公交、地铁、打车、铁路、航班、轮渡、接驳、大巴和包车。
- 精确起终点、线路或班次、换乘、等待、步行、车上时间和门到门时间。
- 费用、购票或操作入口、退改、首末班与停止入场约束。
- 来源、查询时间和动态状态。没有精算能力时提供 `estimated`、依据、耗时区间与缓冲，门到门排程取区间上界加缓冲；不得把估算标为平台路线。地图链接可来自实际可用地图，不要求高德 MCP 或高德 POI。

实时余票、价格和临时班次只表示查询时状态。火车最终由 12306 复核；大巴和包车尽量回到客运站、承运方、平台合同或书面报价。

以下情况至少比较一个包车＋司机或司导方案：多次换乘或首末班无法衔接、起终点远离站场、多人或大量行李、老人儿童或夜间抵达、一天串联多个偏远景点。包车另记录车型、座位和行李容量、计价口径、服务时长、油路桥停车、司机食宿、异地返空、超时、资质、保险、退改和应急联系状态。

## 3. 计算串联顺序

1. 先按地理位置聚成同日片区。
2. 先锁定日出日落、夜景、演出、预约、停止入场和末班交通等强时间窗口。
3. 用门到门时间比较同方向路线，避免折返；跨城按风险增加 30～120 分钟缓冲。
4. 根据步行承受度、行李、夜间和天气切换交通方式。
5. 每半天保留缓冲。明显破坏核心路线的景点移入未采用清单并说明原因。

## 4. 插入餐饮与行李

先根据景点结束时间、下一段交通和真实片区建立餐窗，再按[餐厅候选研究与路线适配](restaurant-research.md)选择具体餐厅。跨过 11:30～13:30 或 17:30～20:00 且未在交通工具内用餐时，创建独立 `meal` 事件；不得把正餐藏在交通、住宿或休息描述中。

景区补给可作为 checkpoint 并引用 `meal_id`；承担正餐时同时创建顶级 meal 事件并通过事件与 checkpoint ID 关联，费用只计一次。

移动日明确退房到入住之间的大件行李去向。跨时区或红眼航班逐项对齐到达日期、住宿夜、凌晨入住或寄存方案。

## 5. 交付主 Agent

结果提交规范化景点、交通边、预约、天气和事件绑定，不直接生成完整日程。每个采用对象必须能回答何时、从哪里进、按什么顺序、最晚何时离开、下一段如何走以及失败时切换什么。
